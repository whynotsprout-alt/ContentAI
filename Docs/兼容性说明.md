# 兼容性说明（Stream 事件）

## 统一对外事件合约
- 所有流式接口统一返回 SSE 事件：
  - `type=token`
  - `type=tool`
- `StreamEventV2` 模型固定字段：`{"type":"token|tool","content":"...", "name":"..."}`。
- 不再支持把旧事件名作为 SSE 的 `event` 类型。

## 接口变更
1. `POST /api/chat/sessions/{session_id}/messages/stream`
2. `POST /api/chat/sessions/{session_id}/resume/stream`

变更点：
- 响应 event 名称仅为 `token`、`tool`、`close`（由 SSE 连接关闭触发）。
- 前端监听必须使用 `source.addEventListener('token', ...)` 与 `source.addEventListener('tool', ...)`。
- `name` 仅作为语义标签（如 `execution_started` / `execution_completed` / `assistant_message_delta`）保留，不作为事件类型分派依据。

## 前端迁移（已落地）
- `frontend/src/stores/workbench.ts`
  - `execution_*` 与 token 的状态驱动逻辑保留在 `token` 分支内部。
  - 删除 `!name` 宽容分支，避免旧 payload 兼容路径。
  - 新增 `tool` 分支仅用于工具事件记录。

## 兼容顺序（禁止回退）
1. 先同步 `backend/src/api/chat.py` 与 `backend/src/agent/runtime/events.py`，确保内部事件已归一化为 `token/tool`。
2. 再更新前端监听分支（`workbench.ts`）与测试事件发送方。
3. 最后执行回归：旧事件名作为 SSE 事件名时返回 400/404/空事件（按契约），不应再被前端解析。

## 运维注意
- 生产环境保留 `backend/src/api/chat.py` 日志告警：当 `StreamEventV2` 收到非法事件类型时直接跳过，并产生日志，便于监控残留旧调用。
