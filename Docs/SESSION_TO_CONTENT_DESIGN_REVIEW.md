# 会话到内容稿件链路设计审查

审查日期：2026-07-15

范围：会话提交、热点采集、候选清洗、筛选与评分、资料搜索、研究包、内容生成、跨轮恢复与审计。

## 总体结论

本文保留最初审查背景；截至同日，热点评分与研究链路的 P0/P1 项已按“双固定搜索工具 → 研究子模型模板归纳 → 持久化资料包”的方案完成修正。当前研究不访问结果网页，不做证据充分性评级；搜索工具结果质量属于受信供应商边界。

本次已将评分子模型输入调整为五个字段：`title`、`url`、`summary`、`platform`、`published_at`。该改动改善了时效、平台和语义判断，但不会自动消除下述结构性问题。

## 缺陷清单

### 已修复：200 条总上限不再系统性挤掉后置来源

- 默认来源现为 18 个 RSS、4 个 TikHub 平台和 AI HOT，共 23 个逻辑平台。
- 采集层按平台逐轮各取一条并循环偏移每轮起点，去重、失败和不足平台释放的容量由其他平台补齐。
- 在每个平台都有 10 条时，200 条池中每个平台至少贡献 8 条，AI HOT 和全部 TikHub 平台都会进入评分。

建议：按来源设置配额或轮询合并，再执行总量截断；把来源覆盖率、截断数和被截断来源写入结果与指标。

### 已修复：评分协议只返回达标候选

- 评分模型仍一次查看最多 200 条，但只返回达到账号标准的 `selected_candidates`。
- 未入选候选不输出 reject、淘汰列表、理由或风险；入选数量由模型决定，后端保持模型顺序。

当前协议避免为全部候选生成详细结构化评价，同时不设置固定返回数量。

### 已修复：删除网页正文抓取与 SSRF 请求面

- 研究阶段只访问固定 HTTPS allowlist 中的 Metaso 与 Anspire API，不请求搜索结果 URL，也不解析其 DNS。
- 供应商文本经控制字符/HTML/长度清洗和提示注入检测后，以独立 HumanMessage JSON 数据块送入研究子模型；命中项被隔离。

### 已修复：研究包可跨轮、跨 Worker 完整恢复

- `ResearchPackage` 保存结构化结论、findings、风险、清理后的双搜索快照、提供商诊断和渲染文本，以 `(execution_id, topic_hash)` 幂等写入。
- 下一轮直接加载会话最新资料包作为只读上下文；不依赖 Assistant 转述或 ToolMessage checkpoint。
- 会话删除时资料包同步级联清理；不保存网页正文。

### 已修复：会话固定 AgentVersion

- `ChatSession.agent_version_id` 在创建时固定，后续 execution 不再查询最新版。
- 历史会话优先回填最近 execution 的版本；没有 execution 的会话回填当前最新版本。

### 已修复：候选使用稳定 ID

- 热点采集优先按 URL 去重，因此相同标题、不同 URL 的候选可以同时存在。
- 评分输入与输出现使用稳定 `candidate_id`，后端按 ID 恢复原候选。

标题仅用于展示；同标题、不同 URL 的候选拥有不同 ID。

### 设计调整：不再进行证据充分性评级

- 产品边界信任 Metaso 与 Anspire 的结果质量，不计算注册域、不猜测原始信源、不要求双源交叉，也不生成 `insufficient`。
- 仅机械移除未知 `source_id` 或工具结果之外的 URL；finding 本身不因引用被清理而删除或降级。

### 已修复：研究使用 180 秒 cooperative deadline

- 双搜索任务共享 30 秒、结构化归纳最多 135 秒，剩余时间用于引用清理、持久化和资源释放。
- 搜索与模型调用共用取消检查；超时或用户取消时取消并等待子任务，关闭异步客户端后再返回错误。
- `prepare_topic_research` 使用 cooperative execution mode，不再套不可中断的外层线程超时。

### P2：最终稿只有长度校验，没有事实与来源验收

- 最终内容由通用主模型自由生成，没有独立 draft schema、引用字段、事实检查节点或人工审核状态。
- API 虽定义了 citations/tool_results 展示结构，但当前持久化路径没有填充这些字段。
- `validate_assistant_response()` 只校验消息类型与最大字符数，不能保证稿件使用了已核验资料，也不能防止新增无来源事实。

建议：把“生成稿件”和“校验稿件”分成两个节点；输出结构至少包含正文、claim 列表、引用映射、未核验项、风险提示和 review_status。发布前必须经过人工确认或明确跳过审核。

## 建议实施顺序

1. 已删除研究网页抓取，只保留双搜索 API。
2. 已让评分输出只保留达标候选，并使用稳定 `candidate_id`。
3. 已持久化研究资料包并固定会话 AgentVersion；不引入固定阶段状态。
4. 已重构研究超时与取消；按产品决策不引入证据独立性评级。
5. 稿件校验节点和人工审核状态仍属于后续可选增强。

## 关键回归测试

- 23 个默认逻辑平台在 200 总上限下每个平台至少进入 8 条（各平台均有 10 条时）。
- 同标题、不同 URL 的候选不会错配评分和链接。
- 200 条输入只返回达标候选，且不要求输出未入选评价。
- 搜索结果中的危险引用链接不会输出，且不会发生网络请求。
- 恶意搜索摘要中的提示注入不会改变研究输出协议。
- 跨轮“获取研究包 -> 确认 -> 写稿”使用同一份完整研究包和同一 AgentVersion。
- 研究超时后不再存在继续运行的底层抓取/模型调用。
- 未知引用被移除，但合法 finding 保留。
