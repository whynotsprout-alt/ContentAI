# 展开完整回复按钮强化设计

## 目标

让长回复下方的“展开完整回复”成为清晰可发现的主操作，确保在浅色、半透明的对话背景上拥有足够的视觉对比和可访问性；展开后的“收起回复”保持同一位置与尺寸，但降级为次级操作。

## 现状与问题

`ChatCanvas.vue` 使用 `.message-expand` 控制长回复的展开与收起。该控件当前为透明背景、无边框、使用 `--wb-muted` 小字号文本；`light-theme.css` 也未覆盖它。在山景等高细节背景上，它难以与普通文本区分，点击目标和操作优先级都不够明确。

## 已确认的设计

### 展开状态

- 文案保持“展开完整回复”，不改变现有功能或展开阈值。
- 使用现有 `--wb-accent` 深绿色实底和白色文字，使其与输入框的“发送”按钮属于同一主操作语义。
- 按钮采用 `inline-flex` 居中布局，最小高度为 40px，水平内边距 16px，使用现有 `--radius-control` 圆角与 600 字重。
- 悬停时切换到既有 `--accent-strong`，并上移 1px；按下时下移 1px。过渡时长沿用 180ms–220ms 的既有交互节奏。

### 收起状态

- 文案保持“收起回复”。
- 通过 `aria-expanded='true'` 切换为浅色半透明背景、深绿色文字和已有线条色边框；它仍清晰可见，但弱于“展开完整回复”的主操作优先级。
- 保持和展开状态相同的最小点击面积、位置和键盘焦点样式，避免界面跳动。

### 约束与验证

- 只修改 `apps/web/src/styles/workbench.css`；不新增颜色、字体、组件或动画，也不调整 Vue 逻辑。
- 使用全局 `:focus-visible` 焦点环，确保键盘可见；按钮原有 `aria-expanded` 保持不变。
- 新增测试验证 CSS 同时覆盖默认、展开、悬停、按下和减少动态偏好所需的规则；然后运行前端单测、构建和现有 Web 校验。

## 验收标准

- 在浅色工作台背景中，折叠长回复下方的“展开完整回复”以深绿色实底、白色文字和不小于 40px 的高度显示。
- 点击后内容完整显示，按钮变为清晰但次级的“收起回复”样式；再次点击仍能折叠。
- 鼠标悬停、鼠标按下与键盘聚焦时都有可辨认反馈，且不影响窄屏布局或其他按钮。
- `npm test`、`npm run build`、`npm run verify:web` 均通过。
