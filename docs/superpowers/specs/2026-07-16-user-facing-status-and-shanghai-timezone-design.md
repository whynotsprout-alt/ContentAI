# 用户状态提示与上海时区设计

## 目标

将 ContentAI 对话工作台的运行状态调整为简短、统一的中文提示。界面不得向普通用户暴露提示词、函数或工具名称、候选数量、来源健康度、错误码、请求标识、会话标识或执行标识。所有用户可请求的当前时间固定为亚洲/上海时区。

## 范围

### 运行状态栏

- 运行中统一显示“评估中”。
- 排队、重连、等待确认、取消中、已取消和失败分别使用简短中文文案。
- 运行状态栏只使用生命周期状态；不读取或渲染 SSE 工具事件中的 `tool_name`、`name`、`progress.label`、候选数量或来源健康度。
- 删除状态栏中的工具详情与来源明细，避免服务器新增内部字段时被意外透出。

### 错误提示

- SSE 和执行失败的用户可见提示不拼接错误码、请求标识、会话标识、线程标识或执行标识。
- 无法归类的内部异常显示为“处理失败，请稍后重试”，不显示原始错误文本。
- 已有明确可操作的账号、限流类中文提示可继续保留。

### 时间

- `current_datetime` 不再接受可变时区参数，始终使用 `ZoneInfo("Asia/Shanghai")`。
- 返回值中的 `timezone` 固定为 `Asia/Shanghai`，日期和时间均由该时区的当前时间生成。
- 事件与数据库的存储时间维持现有语义；本次只限制面向用户的当前时间能力，避免改变审计与排序行为。

## 实现边界

- 前端由生命周期生成状态文案，作为最后一道脱敏边界；后端事件中的进度字段仍可供服务内部使用，但不进入界面。
- 不新增工作流阶段或持久化状态字段，保持现有“对话式流程”的产品约束。
- 不修改现有未提交的发布、打包和运维文档改动。

## 测试与验收

1. 前端组件测试覆盖：即使工具事件带有英文函数名、提示词标签、候选数量和来源明细，运行状态仅显示“评估中”，页面不渲染这些字段。
2. 前端 store 测试覆盖：流式错误包含内部标识时，用户可见消息不包含这些标识。
3. 后端单元测试覆盖：无论调用方传入何种参数（该参数将被移除），当前时间工具返回 `Asia/Shanghai`，并与该时区当前日期一致。
4. 既有前端和相关后端测试继续通过。
