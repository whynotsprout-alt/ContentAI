# ContentAI 聊天工作台布局与轻磨砂视觉设计

## 背景

当前聊天工作台已经具备稳定的 Vue 组件结构、完整的响应式侧栏和统一的 4pt 间距体系。聊天消息、运行状态和输入框均在 `conversation-column` 内居中，但桌面侧栏会把整条对话轴推向视口右侧；在 1440px 及以上宽屏中，用户感知到的聊天区域并不位于页面视觉中心。

现有产品样式还将顶部导航、会话侧栏和输入区统一渲染为不透明白色表面。三条实色结构面形成明显的“顶部白条、左侧白条、底部白条”，圆角体系虽然存在，但缺少克制的透明层次。消息列表本身没有卡片滥用，这是应当保留的优点。

本次调整采用用户确认的方案 A：宽屏建立真正以视口为中心的阅读轴；磨砂只用于结构层；助手正文保持纯净；用户消息仅使用轻微半透明气泡。

## 目标

- 在不改变业务交互和数据流的前提下，让宽屏聊天内容、状态条和输入框共享一条接近视口几何中心的阅读轴。
- 把普通正文阅读宽度从 960px 收束到约 840px，改善长文本阅读舒适度。
- 为顶部导航、会话侧栏和输入面板增加克制的半透明与背景模糊，并提供不支持模糊时的可靠降级。
- 保持助手消息无卡片，避免把每条消息包装成玻璃卡片。
- 调整回合间距和消息头高度，让“用户问题 → 助手回答”关系更紧密，让不同回合之间更清晰。
- 保持现有移动端抽屉、平板紧凑侧栏、键盘操作、焦点管理和安全区行为。

## 非目标

- 不修改聊天业务逻辑、消息数据结构、状态管理、API 或执行流程。
- 不重做顶部导航、会话管理和 Agent 选择交互。
- 不增加主题切换、背景视频、装饰插画或复杂动画。
- 不为助手消息、会话列表或空状态批量增加卡片。
- 不修改管理后台和登录页的视觉表面。
- 不扩大现有 `8px / 12px / 16px` 圆角体系。

## 选定方案

### 宽屏视觉中心

现有 `--session-rail-width` 和响应式 Grid 保持不变。聊天内容不通过绝对定位脱离布局，也不允许覆盖会话侧栏。

- 小于 1440px：聊天轴继续在剩余内容列内居中，优先保证侧栏与正文互不重叠。
- 1440px 及以上：阅读轴使用受约束的负向水平补偿，抵消侧栏造成的视觉偏移，使约 840px 的正文区域接近整个视口中心。
- 补偿同时作用于消息、运行状态、审批面板、输入框和输入提示，保证所有对话表面共用同一轴线。
- 补偿值由侧栏宽度和可用空间推导，不写死为只适配单一截图的像素值。

普通消息正文最大宽度约为 840px。代码块、表格和媒体继续允许在该宽度内横向滚动或自适应，不额外引入脱离主轴的超宽 breakout。

### 结构层轻磨砂

磨砂表面仅用于：

- `.workbench-header`
- `.session-rail`
- `.composer` 输入面板
- 现有 popover 菜单可复用同一结构表面语义

结构表面使用高不透明度的白色混合面，透明度控制在能够保持正文和控件对比度的范围内；使用轻量 `backdrop-filter: blur(...) saturate(...)`，并保留细分隔线。输入区外层 `.composer-wrap` 不再表现为整条实色白色底栏，而是作为透明布局容器，让居中的输入面板成为唯一结构表面。

不支持 `backdrop-filter` 时，结构表面退化为接近不透明的白色，不影响可读性或控件边界。磨砂不依赖背景视频、渐变或高饱和装饰才能成立。

### 圆角与层次

- 控件继续使用 8px 圆角。
- 用户气泡、输入面板继续使用 12px 圆角。
- 抽屉和浮层继续使用 16px 圆角。
- 顶栏和桌面侧栏作为贴边结构，不额外增加大圆角。
- 输入面板可使用短距离、低模糊的小阴影形成悬浮感；若保留完整描边，则阴影必须足够克制，避免“细边框 + 宽柔阴影”的幽灵卡片效果。
- 助手正文继续无边框、无阴影、无玻璃背景。

### 消息节奏

消息排列保持现有单列表达，但用语义间距表现回合关系：

- 用户消息头不再使用无意义的 44px 最小高度；只有复制按钮等真实交互控件保留 44px 点击目标。
- 用户消息与紧随其后的助手回答使用较紧间距，建议 16–24px。
- 助手回答与下一轮用户消息使用较松间距，建议 32–48px。
- 用户气泡保持右对齐，最大宽度低于助手正文，并使用轻微绿色透明表面。
- 移动端相同比例收紧，但不牺牲 16px 页面边距和 44px 触控目标。

空状态保留现有信息和操作，只调整空间节奏：图标与标题组分隔更大，kicker 与标题更紧，正文与操作之间更松。不增加新的装饰内容。

## 组件与样式边界

### `apps/web/src/components/ChatCanvas.vue`

只在确有必要时增加用于回合关系的语义 class；不改变消息渲染、Markdown 清理、发送、取消、复制、展开和审批逻辑。

### `apps/web/src/App.vue`

保留现有 Header、SessionRail、RunActivityBar 和 ChatCanvas 结构。若需要统一对话轴，只通过共享容器 class 或 CSS 变量传递，不引入重复的桌面/移动组件。

### `apps/web/src/styles/product.css`

本次主要改动位置。新增结构表面、阅读轴和消息节奏的语义 token；复用既有颜色、间距、圆角和 transition。不得影响管理后台现有实色表面规则。

### 测试

优先扩展 `apps/web/tests/workbench-responsive-contract.spec.mjs`，以契约方式覆盖：

- `--conversation-measure: 840px` 的桌面阅读宽度，并允许在可用空间不足时自适应收缩。
- 宽屏视觉中心补偿只在安全断点启用。
- Header、SessionRail 和 Composer 使用轻磨砂结构表面。
- Composer 外层不再是一整条实色底栏。
- 助手消息保持透明无卡片。
- 用户消息使用轻透明表面和既有 12px 圆角。
- 不支持模糊时存在高不透明降级。
- 移动、平板和桌面侧栏断点保持原有结构。
- 既有 IME、Enter 行为、抽屉焦点和可访问名称契约不退化。

## 响应式行为

### 手机（小于 768px）

- 保留会话抽屉和遮罩。
- Header 和抽屉可使用更高不透明度的磨砂表面，保证小屏对比度。
- 输入框仍为底部稳定布局，不遮挡最后一条消息或安全区。
- 发送按钮保持 44px 图标按钮。

### 平板（768px–1023px）

- 保留 72px 紧凑侧栏和 280px 展开侧栏。
- 不启用视口中心补偿；内容在剩余区域内居中。
- 展开侧栏时聊天宽度自然缩减，不产生横向滚动。

### 中等桌面（1024px–1439px）

- 保留 248px 或 264px 侧栏。
- 内容在剩余区域内居中，不强行追求视口几何中心。
- 840px 阅读宽度在空间不足时使用 `min()` 和页面 gutter 自适应收缩。

### 宽屏（1440px 及以上）

- 侧栏保持 280px。
- 聊天轴向左补偿以接近视口几何中心。
- 补偿后的 840px 阅读区域不得与侧栏相交。

## 可访问性与降级

- 正文、占位符、次要文字和交互状态继续满足 WCAG AA 对比度。
- 半透明表面上的文字颜色保持使用现有高对比产品 token，不以降低文字不透明度制造“轻盈感”。
- 所有按钮继续保留 44px 最小点击目标和清晰 `:focus-visible`。
- 只使用 150–250ms 的状态过渡，不增加装饰性入场动画。
- `prefers-reduced-motion: reduce` 继续关闭非必要动画和过渡。
- `@supports` 为不支持背景模糊的浏览器提供实色降级。
- 高缩放、窄屏和长中文/英文内容不得产生页面级横向滚动。

## 验收标准

1. 在 2048px 宽桌面上，聊天正文、状态条和输入面板共享同一视觉中心，明显消除当前向右偏移。
2. 在 1440px、1280px、1024px、768px 和 390px 宽度下，聊天区不覆盖侧栏、不产生页面级横向滚动。
3. 顶栏、侧栏和输入面板可感知为轻磨砂结构层；助手正文仍保持无卡片。
4. 用户消息保持右对齐、轻透明绿色表面和 12px 圆角。
5. 用户消息头不再产生 44px 的纯空白高度；回合内部和回合之间具有可辨识的紧松节奏。
6. 不支持 `backdrop-filter` 时，所有结构表面仍清晰可读。
7. 现有 Web 测试、构建和 `verify:web` 通过。
8. 浏览器验证覆盖桌面、平板、手机、键盘焦点、文本缩放和无障碍检查。

## 实施约束

- 使用 TDD：先新增失败的布局契约测试，再完成最小 CSS/模板改动。
- 不修改与本任务无关的工作区变更。
- 实施完成后按 Impeccable `polish` 做视觉、响应式、交互与可访问性收尾。
- 最终重新运行 Impeccable layout detector，未解决或未经用户接受的发现数必须为零。
