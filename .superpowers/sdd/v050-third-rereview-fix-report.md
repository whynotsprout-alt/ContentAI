## Findings

- **TRR-IMP-01 - DONE.** Root cause: `_OwnerLoopAsyncClient._submit_close()` treated a completed close future as non-canonical before its callback completed, allowing an immediate completion/callback race to submit another close; an old callback could also mutate newer state. Interface change: `_close_generation` now identifies the canonical close transition, `_submit_close()` returns an existing canonical future regardless of completion, and `_finish_close(future, *, generation)` rejects stale identity/generation pairs, sets `_async_closed` only on success, and clears the canonical future only after a failed transition. Fresh evidence: the subsequent exact serial integrated rerun exited `0`, `67 passed in 122.27s (0:02:02)`, including `apps/api/tests/test_llm_client.py`. The two previously errored llm nodes also passed in the isolated seven-node rerun (`7 passed in 13.52s`). This serial passing evidence, rather than any inferred cause for the superseded run, supports the DONE disposition.
- **TRR-IMP-02 - DONE.** Root cause: gateway ownership had a one-way synchronous close path, failure could be swallowed during retirement/finalization, and container/service/FastAPI shutdown had no complete awaited retryable async lifecycle. Interface change: `_GatewayOwner` exposes `closed`, `close() -> bool`, and `aclose() -> None`; `RuntimeContainer` retains unresolved owners and exposes `aclose()`; `AgentService.aclose()` closes runner then awaits runtime shutdown; `api.app._shutdown()` is async and awaits awaitable hooks while continuing later hooks after failures. Fresh evidence: the single integrated rerun exited `0`, `67 passed in 122.27s (0:02:02)`, including `test_runtime_container.py` and `test_main.py`. The two previously errored runtime nodes and all three previously failing readiness nodes passed in the isolated seven-node rerun (`7 passed in 13.52s`).
- **TRR-IMP-03 - DONE.** Root cause: `git archive --add-virtual-file` required JSON argument escaping that is not portable across Windows PowerShell hosts. Interface change: `tools/package-ubuntu.ps1` writes UTF-8-without-BOM manifest JSON into a GUID temporary directory, supplies it through `git archive --add-file`, and cleans the file/directory in `finally`. Fresh evidence: `test_release_contract.py` was re-run independently with exit `0`, `7 passed in 6.37s`; its available-host parameterization used `powershell.exe` and performs two isolated archive builds for that host. Windows PowerShell 5.1 AST parsing also exited `0` with no parser output.
- **TRR-MIN-01 - DONE.** Root cause: the terminal-state cancellation regression matrix did not exercise the active-user cancellation consumer, so a stale worker could project cancellation after a competing terminal settlement without that branch being covered. Interface/test change: `test_waiting_input_stale_worker_does_not_project_cancellation_over_terminal_state` now parameterizes completed/failed terminal states against active-user/disabled-user consumers and asserts neither cancellation projection nor terminal overwrite. Fresh evidence: the focused Task 5 selector exited `0`, `4 passed in 10.80s`.
